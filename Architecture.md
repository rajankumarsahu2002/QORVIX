# QORVIX — Architecture

## Tech Stack

Frontend:
- React 19 + TypeScript strict + Vite 6

UI:
- TailwindCSS 3 + shadcn/ui (lightweight LOCAL components under `src/components/ui` — button/card/input/chip/badge/dialog/sheet, no heavy lib)
- Fonts: Inter (primary) + Manrope (alt) via Google Fonts cached by PWA

State:
- Zustand 5, one small slice per feature (`qorvix-syllabus`, `qorvix-batches`, `qorvix-jobs`, `qorvix-timetable`, `qorvix-dashboard`)

Database:
- IndexedDB via `idb` wrapper (`qorvix-db` kv store) as the zustand-persist backend for ALL domain data (`lib/idb.ts` `idbStorage`; pre-migration LocalStorage keys are promoted once, then read from IDB forever)
- LocalStorage ONLY for: theme (`qorvix-theme`), notification queue (`qorvix-notif-queue`)
- No cloud backend, no login, no secrets required for basic operation (§65/§85)

Deployment:
- GitHub + Vercel (`vercel.json` rewrites for SPA + SW headers). HTTPS required for push.

PWA Support (Required):
- `vite-plugin-pwa` autoUpdate, app-shell + fonts runtime cache, offline-first
- `manifest.webmanifest`: name `QORVIX — Your Trajectory to Victory`, short `QORVIX`, standalone, portrait, real PNG icons (`qorvix-192.png` any, `qorvix-512.png` any, `qorvix-maskable-512.png` maskable, generated by `scripts/gen-icons.mjs` from the `QorvixLogo` SVG) + apple-touch-icon
- Push: local-scheduled via Notification API + SW (`src/lib/notify.ts`: permission, deduped queue, `fireDue` polled 60s + on boot). Rules: admit 15d/10d, exam 7/3/1d escalating, answer-key ~10d after Given, routine next-occurrence + 9pm plan nudge. In-app badges/countdowns fallback if denied. No FCM/backend; nothing faked — unsupported platform features degrade to in-app UI.

## Folder Structure (feature-based, scalable, no messy code)

```
src/
  app/            # (folded into App.tsx: providers, root layout, bottom nav, theme, push bootstrap)
  features/
    syllabus/     # store.ts (nodes) + batches.ts (BatchCourse) + logic.ts (heat/status/scores) + UI in App.tsx
    jobs/         # store.ts (jobs/stages + isFullyCleared/nextMilestone) + UI in App.tsx
    timetable/    # engine.ts (deterministic planner) + store.ts + UI in App.tsx
    dashboard/    # store.ts (hours + linked sessions) + UI in App.tsx
  components/
    logo/         # QorvixLogo.tsx (SVG: progress circle + check + target dot + timeline tick)
  lib/            # idb.ts (IDB persist backend), notify.ts, dates.ts, validate.ts (URL + CSV parser)
  styles/         # globals.css (tokens, heat scale, focus states)
  main.tsx  App.tsx
public/  manifest.webmanifest  qorvix-icon.svg  qorvix-192/512.png  qorvix-maskable-512.png  apple-touch-icon.png
scripts/ gen-icons.mjs (regenerates PNGs from the SVG, no deps)
PRD.md Architecture.md Rules.md Phases.md Design.md Memory.md
vercel.json vite.config.ts tailwind.config.js
```

Rules: feature owns its types/store/db/components. Cross-feature reads ONLY via `lib/` + exported types. No `features/jobs` importing `features/syllabus` internals. No backend calls.

## Strategies

- Routing: no router library (4 tabs would not justify it). `Tab` state in `App.tsx` renders Dashboard/Syllabus/Jobs/Timetable; `vercel.json` rewrites all routes to `/index.html` so refresh/deep-linking works on Vercel.
- Validation: `lib/validate.ts` (non-empty, http(s) URL, CSV parser with quoted-comma support); per-store guards (unique sibling titles, fee≥0, priority 1–5, minutes≥10, Subject link mandatory); UI surfaces messages inline, never silent.
- Error handling: every persist/notify/import wrapped; toasts via `alert` only for permission results, inline messages elsewhere; empty states guide the next action; corrupted persist shapes guarded with `Array.isArray` fallbacks.
- Import/export: JSON + CSV map into the same node chain via shared `ensureInto` (no duplicates, skipped counted); preview counts + samples before Confirm; no export yet (single-user local-first, no backend to sync to).
- State: one small Zustand slice per feature, persisted to IndexedDB; domain math lives in `features/*/logic|engine`, never only in JSX.

## App Flow

1. Syllabus (master, once, hybrid source + reusable batches) →
2. Job Recorder links syllabus+weightage per stage (Subject mandatory) + Target links + Target→Active carry + Merge groups →
3. Timetable engine reads active+target/priority/dates/progress/mistakes/staleness → night-generate tomorrow To-Do (CA daily/Friday-weekly/month-end, mocks Tue/Thu/Sat, analysis Mon/Wed/Fri, Sunday caps, Math/GK bias) → user reviews (reorder/minutes/remove/remake/source) → Done completes syllabus node → today auto-shift-only →
4. Dashboard shows today items + routine + next-uncleared countdowns + pending revision + linked timer sessions/trend.
Weakness (mistakes+staleness) and completion flow back into the next plan — the full §81 loop.

Verified AI-Studio prompt mapping (structure-only, adopted): AppBar (title left, menu right) + pill search + horizontal chip tabs with count badges → used for Jobs/Academics/Targets filter. Status-timeline cards (left vertical pill, middle title/subtitle/banner, right ✓/✗/○ badges) → used for Job cards. FAB above bottom nav, Telegram floating-island bottom nav with active pill, dark slate theme → used app-wide. Omitted: avatar nav item (single-user, no social).

## PWA + Push Detail

- `vite-plugin-pwa` workbox: precache shell (now 14 entries incl. PNG icons) + `globPatterns **/*.{js,css,html,svg,woff2}`, runtime CacheFirst fonts.
- `lib/notify.ts` schedules routine next-occurrences + nightly plan nudge on boot, admit/exam/answer-key by date-diff; `fireDue` polled 60s. No FCM/backend.
- Icons: `scripts/gen-icons.mjs` renders `QorvixLogo` shapes to 192/512 any + 512 maskable (safe-zone zoom) + apple-touch 180.
